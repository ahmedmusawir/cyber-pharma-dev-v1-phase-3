# FIX-001-CYBER-PHARMA — KIP-2 Kill: Server-Resolved Identity on the Public Nav (+F02)

## Context

`MobileNav` and `UserMenu` read `role` from localStorage-persisted Zustand state (written only by `login()`). A cookie-authenticated user with cleared/absent localStorage gets wrong role-gated nav UI on the live landing page (`/`), where both components are mounted via `NavbarHome` ← `(public)/layout.tsx`. This is KIP-2, promoted HOT by recon 2026-08-11. Cure = the Navbar Law (proven in-repo on the authed `Navbar`): identity is server-resolved and passed as props, never gated on client-persisted state. F02 rides along: `src/instrumentation.ts:5` comment cites `.env.local.example`; the real file is `.env.example`.

## Design (per manager R1–R4; Operator ratified 2 flags via Q&A)

**F01 — the fix.** Mirror `profile/layout.tsx` → `Navbar` pattern, redirect-free:

1. **`src/app/(public)/layout.tsx`** — becomes the identity resolver:
   ```tsx
   const supabase = await createClient();            // @/utils/supabase/server — consumption, not modification (V8)
   const { data } = await supabase.auth.getUser();
   const user = data?.user ?? null;
   const role = user ? await getUserRole(user.id) : null;   // @/utils/get-user-role
   ...
   <NavbarHome user={user} role={role} />
   ```
   No redirects — logged-out visitors are legitimate here.
2. **`NavbarHome.tsx`** — accepts `{ user: SupabaseUser | null; role: AppRole | null }`, forwards to `<UserMenu user role />` and `<MobileNav user role />`; also mounts `<NavAuthRefresh />` once. Stays a server component.
3. **`MobileNav.tsx`** — props replace: store role read (line 22), local `user`/`isLoading` state, the whole `fetchUser` useEffect + listener, and the client `createClient` import. Renders synchronously from props (no loading window). **Keeps** `useAuthStore.getState().logout()` (Operator-ratified: action call mirrors cured Navbar.tsx:102).
4. **`UserMenu.tsx`** — same surgery: props in, client fetch/listener/loading out. `<Logout />` usage unchanged.
5. **NEW `src/components/global/NavAuthRefresh.tsx`** (Operator-ratified) — ~20-line client component rendering null; `onAuthStateChange`: `SIGNED_IN`/`SIGNED_OUT` → `router.refresh()`. Preserves today's cross-tab nav reactivity with a single listener (both nav components are always mounted, so per-component listeners would double-fire).

**F02** — `instrumentation.ts:5`: `.env.local.example` → `.env.example`. Nothing else in the file.

**Consequence (flagged, inherent to R1):** `cookies()` in the layout makes `/` and `/access-denied` dynamic (ƒ) instead of prerendered — the landing page becomes per-request SSR with up to 2 sequential server roundtrips (getUser + role query) for authed visitors, 1 for anonymous. This is the cost of server-resolved identity the manager ratified; route-count stays 22 but the build symbol for these routes changes.
