## 5. 404 matrix method

**Server: the standalone server — `node .next/standalone/server.js`.** It is what `output: "standalone"` actually ships and it runs without the `next start` warning. Recon R3 did not exercise it, so if it fails to boot I stop and report — I do not silently fall back to `next start`.

**Two facts that shape the method:**
1. `NEXT_PUBLIC_*` values are inlined at **build** time, so a flag state is only honest if the flag is set for the build *and* the serve. → one fresh build per flag state.
2. `.env.local` defines the flag key, and Next loads `.env.local` automatically. A truly "unset" shell would silently inherit that value. Next never overrides a key already present in `process.env`, so the "unset" state is run as **explicit empty string** (same technique as recon R3 Build A). → C-07.

**Placeholder env (per command only; never exported to the shell session; `.env.local` untouched):**

```

NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=placeholder-publishable
SUPABASE_SECRET_KEY=placeholder-secret
NEXT_PUBLIC_SITE_URL=http://127.0.0.1:36055
```

`.invalid` (RFC 6761) cannot resolve, so no live Supabase contact is possible even by accident. All four satisfy the boot check in `src/instrumentation.ts:11-32`.
