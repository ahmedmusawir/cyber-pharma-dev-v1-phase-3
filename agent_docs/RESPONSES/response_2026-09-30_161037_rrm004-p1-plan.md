**Recommendation for DD-2: REMOVE.** Delete `next.config.js:5-12` entirely:

```
  images: {
    remotePatterns: [
      {
        protocol: "https",
        hostname: "res.cloudinary.com",
      },
    ],
  },
```

so that `reactStrictMode: true,` is followed directly by `async headers() {`. If you rule "narrow" instead, the block becomes:

```
  images: {
    remotePatterns: [
      { protocol: "https", hostname: "res.cloudinary.com", pathname: "/dyb0qa58h/**" },
    ],
  },
```

That option has no consumer to cite, which argues against it.

**R-009 facet:** the auth matcher at `src/proxy.ts:10` excludes `_next/image`. That is by design, because public pages render images for signed-out visitors. The risk was that the unauthenticated optimizer would fetch and transcode **any** `res.cloudinary.com` URL, which is an attacker-chosen remote input into sharp/libheif. With `remotePatterns` removed, the optimizer only accepts relative `url=` paths, so it can only serve files already under `public/`. The facet closes without touching `proxy.ts`. At P1 I confirmed that the optimizer already refuses an unlisted host with `400 "url" parameter is not allowed`, before any fetch.

At the RRM-003 baseline (`git show 3d2e655…:src/components/common/MultiSelect.tsx`), the component had only a `document` Escape listener, registered while open, and no key handling on the trigger. `Navbar.tsx:82-84` handles Escape only. There is no `<form>` around the rail (`FilterRail.tsx`).

A static read can't settle which; only a runtime probe can, and the RRM-004 QA preflight already has an Enter-vs-Space row. No change is proposed; this stays in the E-18 backlog.
