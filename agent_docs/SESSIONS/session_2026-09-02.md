## Lessons Learned

- **A spec can be wrong while the implementation is right.** E-6 was pure prose: both denial shapes were already in the X4 evidence (A3.1 `42501`, A2.2 0-affected); the spec's single-shape wording simply couldn't describe both. Independent QA caught what Engineering's own evidence already contained.
- **Denial shape depends on which clause denies** (F-14) — `USING` → 0 affected, no error; `WITH CHECK` → `42501`. "Any non-ALLOW is DENY" hides a policy denying for the wrong reason, or a missing `WITH CHECK` entirely.
- **Don't fix the instrument after it certifies the specimen.** CF-8's six harness improvements were recorded, not executed, precisely because changing harness code post-PRE-Q would invalidate what QA had just cleared.
- **The recovery doc rots quietly.** Known Good State sat three modules stale (BIM-000 HEAD, 26/120 board, KIP-2 "open") until read line by line. It is the first thing read after a crash and the last thing anyone thinks to check.
- **Branch labels drift faster than commits.** Same SHA, two branch names, and the spec named a third context — worth stating identity as *branch + SHA + role* rather than a bare branch name.
